一、链路：改哪里，怎么生效

① config/ ← 你只改这里 sources.json 采集源 · topics.json 主题分组 · settings.json 调度与过滤
↓ push 到 main 自动触发
② ai-news-apply-config.yml 校验配置 → 打包 Worker → 单元测试 → 注入 D1 id → 迁移+部署 → 验证线上 API
↓ 配置被编译进 Worker，所以只改仓库文件不够，必须重新部署
③ 每日 07:17（北京）定时采集 ai-news-collect.yml 按 sources.json 并发采集 → 关键词过滤 → 写 Cloudflare D1
↓
④ Cloudflare D1 + Worker D1 存 30 天数据 · Worker 提供 /api/news、/api/status 与只读 MCP
↓
⑤ Agent 读 API → 按 config 参数出选题简报 提示词见 docs/workbuddy.md，其中不含选题参数——改配置即改产物

关键 现在改源、改分类、改过滤都不需要改代码。改造前这三处全部硬编码，改配置等于改程序。

二、三个常见定制动作

1. 加一个采集源

编辑 config/sources.json，追加一条：

{
  "name": "量子位",
  "type": "feed",
  "url": "https://www.qbitai.com/feed",
  "category": "ai_industry",
  "lang": "zh",
  "enabled": true
}
  • name 必须唯一，重复会被校验拦下
  • category 必须是 config/topics.json 里已定义的 id
  • 想临时停用：把 enabled 改成 false，不占数量配额，也不用删
  • 本地先验两步：python scripts/validate_config.py，再 python scripts/collect.py --dry-run --output probe.json

2. 加主题 / 换选题方向

编辑 config/topics.json 加一个 id、中文名和 angle（这个主题怎么判断值不值得做），再回 sources.json 把相关源的 category 指过去。

3. 改过滤与产物

config/settings.json：

  • filter.exclude_keywords — 合规红线，命中的条目采集阶段就丢掉（默认已覆盖美股港股、币圈合约杠杆、外汇、赌博、色情、诈骗刷单）
  • filter.include_keywords — 留空表示不过滤；填了就只保留命中的
  • digest.* — 每主题几条、主题顺序、每个选题至少几个数字
  • targets — 产出公众号 / 抖音 / 小红书哪些平台的稿子及其字数与语气

另外，单个源也能加 include_keywords（源级收窄）。热搜榜、泛科技媒体这类来源没有主题边界，不收窄就会把非相关内容灌进选题池。

X（Twitter）是怎么采的

官方 API 免费层每月仅 1500 条、Basic 档 $200/月起，不划算。改为经 Nitter 镜像读取——每个实例都提供 RSS，直接当 feed 源用，不需要任何账号或密钥：

https://nitter.jaydenha.uk/sama/rss                          → 账号时间线
https://nitter.jaydenha.uk/search/rss?f=tweets&q=AI%20agent  → 关键词实时流

配置里给这类源加了 canonical_host: "x.com"，把镜像链接归一化成原站链接。作用有两个：跨实例的同一推文能正确去重（否则多实例冗余毫无意义），以及你引用到的是 x.com 原链而不是镜像链。

实测 Actions 上 9 个 X 源全部成功（6 个账号 + 3 个关键词，约 154 条）。Nitter 实例的稳定性是最大变量——X Corp 虽在 2026-08 发过 cease-and-desist，但项目已恢复运营、可用实例数超过封杀前。实例失效时只需换这一处 URL，实例列表在 Nitter wiki 上。

注意 部署在 Actions 上的源，本机大陆网络测不通不代表不可用。Reddit、YouTube、Hugging Face 本机全部超时，但在 Actions 上 Reddit 和 Hugging Face 都能通。判断可用性一律以 Actions 实采结果为准。

四、已知限制（都已实测确认）

限制实测结论与出路
热搜源在 Actions 上 403 60s 公开 API 对 GitHub Actions 的数据中心 IP 返回 403；本机访问正常（三种 UA 均 200），所以不是请求头问题。四个热榜源已置 enabled: false 避免每天产生失败噪音。
要恢复：自建 RSSHub / 反代，或改由本机定时任务采集。
workers.dev 在大陆不可达 DNS 被污染（解析到 108.160.169.185）+ 直连超时，因此本机无法直连 Worker API。
验证一律走 GitHub Actions（smoke.mjs 就是干这个的）。要让本机/手机能访问，需绑自定义域名。
36氪 / 机器之心 RSS 已下线 请求 /feed、/rss 返回的是 HTML 页面而非 XML。已标 html_scrape 待适配，但这两站是 JS 渲染，抓不到内容，需改用其数据接口。当前置停用。
Indie Hackers / V2EX 待验证 本机（大陆）网络超时，未能确认。Actions 海外网络可再试，确认可采后把 enabled 改回 true。
泛科技源会带进非 AI 内容 钛媒体、稀土掘金已加 29 个 AI 关键词收窄。觉得过滤太狠就删掉该项的 include_keywords。

五、排查

现象先查这里
push 后没部署改的文件是否落在触发路径内：config/**、src/**、scripts/collect.py。只改 tests/ 或 docs/ 不会触发部署，这是有意设计。
Actions 报配置校验失败本地跑 python scripts/validate_config.py，它会逐项指出哪个文件、哪一项、什么问题。
某个源一直是 0 条0 条且状态 ok = 源正常但没新内容或全被关键词过滤，不等于故障。看 /api/status 的 latest_run.sources 区分。
线上数据像旧的看 stale 字段与 last_success_at；filtered_out 字段说明有多少条被合规规则挡掉。
部署失败要回滚Cloudflare 控制台可回滚到上一版本；本次改造前的线上源码已备份在本地 _backup/cloud-2026-09-15-worker.js。
